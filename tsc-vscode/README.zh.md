# CodeX TSC

[中文](README.zh.md) | [English](README.en.md) | [Русский](README.ru.md) | [日本語](README.ja.md)

在 VS Code 中用段落、事件和连线编写 TSC，再编译成原引擎使用的 GSC。
提供 **SevenBridge 日文版**与 Forest 配置。插件在 `codex/tsc-vscode` 分支，不在扩展市场发布。
它不是 Ren’Py 生成器，也不会创建、复制或修改游戏 EXE。

## 安装

1. 安装 VS Code 1.74 或更新版，以及本分支的 LiarsoftTool；编辑器需要其 `--inspect-tsc` 接口。
2. 在扩展菜单选择“从 VSIX 安装”，打开本地生成的 VSIX。
3. 在设置中搜索 `liarsofttool`，填写已安装程序的路径。插件不会自动下载编译器。

操作需要信任工作区。远程工作区中的编译器也应安装在远程端。
受限模式只提供源码高亮，不运行工具。菜单、编辑面板和插件提示跟随 VS Code 的中文、日语、英语或俄语设置；其他语言回退为英语。
界面语言不改变工程的目标编码或已有剧情。编译器诊断和系统错误保留原文。

## 从空白开始

1. 准备一份独立、已解包的正版游戏资源工作副本；原件保持只读。资源路径与创作工程必须分开。
2. 命令面板执行 **CodeX TSC: 新建 TSC 工程**，选择 SevenBridge、资源副本与新工程目录。
   首个场景默认编号为 `2001`。
3. 在“开始”段落里添加对白、背景、立绘、音乐、音效、语音或等待事件。
4. 添加段落、条件、选项或结束节点，拖动输出端口连到目标节点的输入端口。
5. 保存后点击“构建”。输出位于工程内 `build/`，不会自动安装进游戏。

工程的 `scr/*.tsc` 保存剧情，`assets/` 保存导入的素材副本；`tsc.project.json` 保存引擎、
资源目录、角色、变量、素材映射、输出编码和相对输出目录。可通过“工程设置”修改。
TSC 始终为 UTF-8；输出 GSC 默认 CP932。目标游戏必须能够读取所选编码。

## 编辑与资源

- 段落内事件可上移、下移或删除；对白可直接修改。高级参数供已有脚本和原始命令使用。
- 条件比较整数变量，选项支持 1–5 项。先添加命名变量，再选择条件或赋值、增加、减少事件。
  寄存器编号须自行确认未被原游戏占用；插件不会为原游戏保留空闲区域。
- 角色名关联原引擎的 `gfNNN` 姓名牌；`999` 表示旁白。需要新姓名图片时，作为姓名牌素材导入。
- 支持导入 PNG/JPEG/BMP 图像和 OGG/WAV 音频。为素材指定名称与编号，事件中可按名称提示选择编号。
  编号与原资源重复时，仅导出目录内生成同名替换资源。
- 构建将图像转为 WCG、OGG 转为 PCM WAV；原游戏素材不会被覆盖。
  SevenBridge 的语音按 10000 分组，例如 `10001 → voice/1/0001.wav`。

“源码”可随时切回普通文本编辑器；右键文件“重新打开方式 → 打开剧情图”可返回。
改名会同步本文件内的标签引用；被引用的节点不能直接删除。错误脚本只能查看，修复后恢复编辑。
未知命令、原注释及 GSC 元数据不会因打开图形页而被重写。
节点位置与事件分组写在 TSC 注释中，不另存一套剧情文件。

## 预览与放入游戏

静态预览显示可确定的背景、立绘、姓名牌和对白；音频需手动试听。
`.meta.xml` 提供 LWG 帧的坐标，当前仅预览第一帧。
多前驱节点可选择预览上下文；循环、动态表达式、非默认锚点和未模拟指令会提示限制。
预览不执行原引擎，不验证文字排版、特效、菜单或完整剧情流程。

SevenBridge 使用 `modern-36 / rscript18` 新建脚本；原作入口为 `0100 → 0110 → 2001`。
Forest 使用 `legacy-28 / early`，首段剧情通常从 `1000` 开始。
导入已有 TSC 时保留其参数表，不自动改写方言。
导出的场景仍依赖原游戏的初始化、菜单与素材。请自行将 `build/` 中的文件封包或放入
**独立原引擎测试副本**实际读取的资源位置；不要覆盖正版原件。程序不自动部署或启动游戏。
转换选项请运行 `liarsofttool -h` 查看。

单文件的“检查已保存文件／将已保存文件编译为 GSC”仍可独立使用，采用 VS Code 的
编码和输出目录设置；工程“构建”采用 `tsc.project.json`。单文件输出目录留空会写在 TSC 旁，可能替换已有 GSC。
检查结果显示在“问题”面板，工具错误详情在“输出 → LiarsoftTool TSC”。
Windows 旧转换入口仍受系统代码页的路径限制；失败时应使用可由系统编码表示的路径。

## 本地构建

需要 Node.js 22 或更新版，以及已构建的本分支 LiarsoftTool：

```bash
cd tsc-vscode
npm ci
npm test
npm run package -- --out liarsofttool-tsc.vsix
```

测试可用 `LIARSOFTTOOL_PATH` 指定编译器。
