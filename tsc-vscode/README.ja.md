# CodeX TSC

[中文](README.zh.md) | [English](README.en.md) | [Русский](README.ru.md) | [日本語](README.ja.md)

VS Code の段落ノード、イベントと接続で TSC を作成し、元のエンジン用 GSC にコンパイルします。
現在は **SevenBridge 日本語版を優先**し、Forest 用設定も同梱しています。
`codex/tsc-vscode` ブランチで開発中で、Marketplace では公開していません。Ren’Py プロジェクトの生成や、ゲーム EXE の作成・コピー・変更は行いません。

## インストール

1. VS Code 1.74 以降と、このブランチの LiarsoftTool を用意します。エディターには `--inspect-tsc` が必要です。
2. 拡張機能メニューの「VSIX からのインストール」でローカルビルドの VSIX を選びます。
3. 設定で `liarsofttool` を検索し、インストール済みプログラムのパスを指定します。自動ダウンロードはしません。

操作にはワークスペースの信頼が必要です。リモート作業ではリモート側にもコンパイラーを設置してください。
制限モードではソースの構文強調のみ利用できます。メニュー・編集パネル・拡張機能のメッセージは VS Code の中国語・日本語・英語・ロシア語設定に従い、それ以外は英語で表示します。
表示言語を変えてもプロジェクトの文字コードや既存のシナリオ本文は変更しません。コンパイラーの診断とシステムエラーは原文のまま表示します。

## 新しいシナリオ

1. 正規に所有するゲームの素材を展開し、独立した作業用コピーを用意します。原本は読み取り専用にし、素材と制作プロジェクトを分離してください。
2. **CodeX TSC: TSC プロジェクトを新規作成**から SevenBridge、素材コピー、新規フォルダーを選びます。最初のシーン番号は標準で `2001` です。
3. 「開始」段落に台詞、背景、立ち絵、音楽、効果音、ボイス、待機を追加します。
4. 段落・条件・選択肢・終了ノードを追加し、出力ポートを次のノードの入力にドラッグします。
5. 保存して「ビルド」を押します。出力はプロジェクトの `build/` に保存され、ゲームへの自動配置はしません。

シナリオは `scr/*.tsc`、取り込んだ素材のコピーは `assets/` に保存します。
`tsc.project.json` は対象エンジン、素材パス、キャラクター、変数、素材番号、出力エンコーディングと相対出力先を保持し、「設定」で開けます。
TSC は常に UTF-8、GSC の標準は CP932 です。ゲームが対応するエンコーディングを選んでください。

## 編集と素材

- イベントの上下移動・削除と台詞の直接編集ができます。既存の命令には詳細パラメーターも利用できます。
- 条件は整数変数を比較し、選択肢は 1〜5 件です。先に名前付き変数を登録し、条件や代入・加算・減算で選びます。
  元のシナリオが使用していないレジスターを確認してください。空き領域の予約は行いません。
- キャラクターは元の `gfNNN` 名前画像に対応し、`999` は地の文です。新しい名前画像は名前素材として追加します。
- PNG/JPEG/BMP と OGG/WAV を取り込めます。名前と番号を指定すると、イベントの番号欄で素材名を参照できます。
  元の素材番号と重複しても、置換用ファイルは出力先にだけ生成します。
- ビルド時に画像を WCG、OGG を PCM WAV に変換し、元の素材を上書きしません。
  SevenBridge のボイス番号は 10000 単位で分類します。例：`10001 → voice/1/0001.wav`。

「ソース」で通常のエディターに戻り、「エディターを開き直す → シナリオグラフを開く」でグラフに戻れます。
ラベル名変更では同じファイルの参照も更新します。参照されているノードは直接削除できません。エラーのあるソースは修正まで閲覧専用です。
グラフを開くだけでは未知の命令、元のコメント、GSC メタデータを書き換えません。
ノード位置とイベントのまとまりは TSC のコメントに記録し、別のシナリオデータベースは作りません。

## プレビューとゲームでの確認

静止画プレビューでは確定できる背景、立ち絵、名前画像と台詞を表示します。音声は手動で試聴します。
LWG の座標は `.meta.xml` を参照し、最初のフレームのみ表示します。
合流ノードでは前段を選べます。循環、動的な式、標準外のアンカーと未対応命令には制限を表示します。
元のエンジンを実行するものではなく、文字組み、効果、メニューや物語全体の動作を保証しません。

SevenBridge の新規ソースは `modern-36 / rscript18`、元の開始経路は `0100 → 0110 → 2001` です。
Forest は `legacy-28 / early`、最初のシナリオは通常 `1000` です。
既存 TSC の形式は保持し、暗黙に統一しません。
出力したシーンにも元の初期化・メニュー・素材が必要です。`build/` のファイルを封包するか、
**元のエンジンの独立したテスト用コピー**が実際に読む場所へ配置してください。原本を上書きしないでください。自動配置やゲーム起動はしません。
変換オプションは `liarsofttool -h` を参照してください。

保存済みファイルの検証・コンパイルはプロジェクトなしでも利用でき、VS Code のエンコーディングと出力先設定を使います。
プロジェクトのビルドは `tsc.project.json` を使います。単体出力先が空欄なら TSC の隣へ出力し、既存 GSC を置換する場合があります。
診断は「問題」、実行エラーの詳細は「出力 → LiarsoftTool TSC」で確認します。
Windows の旧変換入口にはシステムコードページのパス制限が残るため、失敗時は表現可能なパスを使ってください。

## ローカルビルド

Node.js 22 以降と、このブランチでビルドした LiarsoftTool が必要です。

```bash
npm ci
npm test
npm run package -- --out ../build/liarsofttool-tsc-0.2.0.vsix
```

テストのコンパイラーは `LIARSOFTTOOL_PATH` で指定できます。`npm run build` はオフライン用フロントエンドを生成します。
`node test/browser.js` は一時的な SevenBridge テストプロジェクトを localhost のみで公開し、終了時に削除します。
