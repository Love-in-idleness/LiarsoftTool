## Область применения

Загрузчик и хост не привязаны к Forest; адаптеры файлов и текста рассчитаны на проверенный EXE.
Первый адаптер поддерживает только указанную ниже сборку Forest. Адреса — VA при предпочтительной
базе загрузки, кроме явно обозначенных RVA слотов импорта. Проприетарный код DLL и игровые ресурсы
в репозиторий не включены.

## Исследованные файлы

| Файл | SHA-256 |
| --- | --- |
| Forest `Forest.exe` | `8eb71d07304d362ec26cc47d93c6ef5854b5acadd7c9fe941755ad50820a3e56` |
| CodeXRScript / патч OC `RsComp.dll` | `6c65c3545a559b6e4a01d54fdb2f57ad4e605b27dc73959cde18bd3468f3cb30` |
| UBAI `RsComp.dll` | `0b1c3cdfc1587f576c30c09b3faa329e88e18fdaddfc0655d1ad398c1654a6a9` |
| Albatross `rsinit.dll` | `43499ada89a18735707c0e33d9a9bb585022e8e1b9b93e562a5e41bbb8340eb6` |

Обе RsComp — 32-битные PE с экспортом `Compile`, RVA соответственно `0x124e` и `0x7090`.
Forest загружает компилятор в `0x412eb0`; `0x4135f0` оборачивает вызов с четырьмя аргументами.
Результат передаётся объекту движка: это не независимый интерфейс с именами входного и выходного файлов.
Сами компиляторы не управляют изображениями, звуком и выводом Unicode.
Поэтому новая реализация использует отдельный хост и необязательные DLL, а не выдаёт замену
`RsComp.dll` за универсальное решение для всех игр.

## Файловые пути Forest

| Адрес | Наблюдение и ограничение |
| --- | --- |
| `0x4247c0` | Сначала отдельный файл через CFile, затем архив |
| `0x42a970` | CFile вызывает `CreateFileA` только для чтения, `OPEN_EXISTING` |
| `0x42ab20` / `0x42ab80` / `0x42abe0` | Чтение, позиционирование и размер CFile |
| `0x413200` | Открытие `%s\\%04d.gsc`, чтение заголовка в 28 байт и следующих секций |
| `0x428260` / `0x4288d0` | Формирование путей LIM / WCG; декодер определяется запросом |
| `0x424b50` | Открытие компонента LWG |

Адаптер заменяет только пять слотов импорта игрового EXE:

| Windows API | RVA |
| --- | --- |
| `CreateFileA` | `0x59098` |
| `ReadFile` | `0x5907c` |
| `SetFilePointer` | `0x590c8` |
| `GetFileSize` | `0x590cc` |
| `CloseHandle` | `0x5909c` |

Найденная подмена становится файлом в памяти; иначе оригинальный API и игра обрабатывают отдельные
файлы и XFL. Глобальных перехватов NT API нет. Запрос LIM должен получать байты LIM, а не переименованный
WCG. Подменяемые скрипты должны сохранять формат Forest legacy-28; modern-36 другой игры отклоняется.
Конвертация изображений, аудио, LWG и TSC использует существующее ядро, включая общий разбор `.meta.xml`.

## Подключение Unicode

Парсер в `0x438790` обходит одно- и двухбайтовые символы; `0x438836–0x438842` формирует
16-битный код, `0x438866` продвигает указатель на два байта. Пути глифов около `0x4453e0`,
`0x445760`, `0x445ab0` и `0x445e70` вызывают ANSI GDI.
Прямое чтение UTF-8 в этих местах неверно разделяет символы; одной смены кодировки недостаточно.

`0x44880c` читает таблицу классификации статического CRT по адресу `0x48fa00`;
`0x44bfb8` заполняет её, получая системный `GetACP` через `0x44c165`.
Поэтому модуль Unicode также заставляет слот `GetACP` самой игры (RVA `0x59184`) возвращать 932:
внутренние двухбайтовые номера правильно распознаются и в неяпонской системе.
Региональные настройки Windows и вызовы `GetACP` других модулей не изменяются.
Основания REA: `ev_fec16cd0f7502d87c643ce4be10a0f513fed452271d3d9e2470c33a9fc4ff9a2`
и `ev_17e895a8bdb39082341c3f9bdb782e5e4ef09b18431096f0819b17088726f365`.

Первая версия сохраняет инструкции и управляющие последовательности. Символы, без потерь проходящие
через CP932 туда и обратно, сохраняют исходные байты; остальные символы BMP получают стабильные номера
из пользовательского диапазона CP932 `F0–F9`. При выводе номер восстанавливается в настоящий Unicode:

| Исходный импорт | RVA | API для подменённых символов |
| --- | --- | --- |
| `GetGlyphOutlineA` | `0x59038` | `GetGlyphOutlineW` |
| `TextOutA` | `0x59024` | `TextOutW` |
| `GetTextExtentPoint32A` | `0x5903c` | `GetTextExtentPoint32W` |

Текст без таких номеров продолжает использовать исходный ANSI API. Номера, занятые исходными скриптами
и EXE, резервируются. Словарь безопасно сохраняется в пользовательские данные до передачи скрипта,
чтобы сохранения и история не меняли смысл после перезапуска. Это не замена непредставимых символов
на `?`, но и не полноценная система Unicode-вёрстки: максимум 1880 дополнительных символов BMP
за вычетом исходных занятых номеров, без дополнительных плоскостей и общего сложного шейпинга.

## Что показывает Albatross

Исследованный `rsinit.dll` содержит 361 экспорт OpenGL, встроенные ресурсы и перехваты времени исполнения.
Инициализация в `0x623af440` достигает NT API файлов; `0x623b15e0` также обрабатывает окна,
шрифты и жизненный цикл модулей. Замены шрифтов в `0x623af370` / `0x623af750` принудительно
задают набор `0x86`: это путь GB2312, а не готовая поддержка UTF-8.
`0x623b45f0` меняет защиту памяти и создаёт переходные участки кода.

Это подтверждает возможность менять ресурсы, окна и текст через DLL без перезаписи EXE на диске,
но не универсальную совместимость разных версий. Для нового движка по-прежнему нужно проверять
соглашения вызовов, структуры данных и вывод текста. Наблюдения использованы для выбора подхода;
проприетарная реализация не копировалась и не стала зависимостью.

## Границы проверки

Переносимые тесты проверяют приоритеты подмены, ошибки без скрытого перехода к другому файлу,
границы путей, раскладку компонентов, неизменность входных данных и словари глифов.
Тесты Windows / Wine дополнительно проверяют загрузку до точки входа, ABI и откат при ошибках,
файловые API и вывод Unicode через GDI. Тесты с моделью таблицы импорта отделены от запуска настоящей игры.
Успешный запуск не проверяет полное прохождение, старые сохранения и все шрифты.
Настоящая Windows и другие версии EXE требуют отдельной приёмки.

На независимой копии игры проверки Wine достигли заставки и титульного экрана, загрузили подмены TSC / PNG.
В кадре оригинального движка подтверждены японский текст, упрощённый китайский, латинские символы вне CP932
и команды цвета из тестового скрипта. Ручной инструмент [game_smoke.cpp](tests/game_smoke.cpp)
завершает только собственный проверенный дочерний процесс игры. Он не входит в стандартный запуск CTest;
игровые ресурсы для теста не поставляются.
