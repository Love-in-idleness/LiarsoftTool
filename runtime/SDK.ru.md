# Разработка DLL

[中文](SDK.zh.md) | [English](SDK.en.md) | [Русский](SDK.ru.md)

Это минимальный интерфейс DLL для будущих расширений, а не универсальный SDK игрового движка.
Публичный интерфейс описан в [rscript_plugin.h](include/rscript_plugin.h), полный минимальный пример —
[log_plugin.cpp](examples/log_plugin.cpp). Запуск описан в [руководстве пользователя](README.ru.md).

## Экспорт и инициализация

Используйте 32-битный Windows-компилятор, совместимый с хостом и игрой. Экспортируйте:

```c
const RScriptPluginDescriptor* RSCRIPT_CALL
RScriptPlugin_GetDescriptor(uint32_t host_abi);
```

Добавьте `RSCRIPT_EXPORT` из заголовка, а в C++ также `extern "C"`.
Текущий ABI — `RSCRIPT_PLUGIN_ABI == 1`; для неподдерживаемой версии возвращайте нулевой указатель.
Дескриптор, ID и имя должны оставаться действительными до завершения процесса.

- Заполните размер структуры, версию ABI, уникальный ID, имя в UTF-8 и функцию инициализации.
- Для обычного расширения задайте `features = 0`. Встроенные функции файлового подключения, ресурсов и Unicode нельзя регистрировать повторно.
- `initialize(context)` возвращает `0` при успехе, другое значение — при ошибке. Подробности выводите через `context->log`.
- Сначала проверьте размер и версию контекста. Пути передаются как заимствованные UTF-16, ID, имена и журнал — в UTF-8.
- Копируйте данные, необходимые после инициализации, включая пути и строки; не сохраняйте заимствованные указатели.

Сначала хост инициализирует файловое подключение, затем ресурсы, Unicode и остальные расширения.
Обычные расширения идут в порядке выбора пользователя; общего механизма разрешения зависимостей нет.
Повторный ID, конфликт встроенных функций или несовместимый ABI прерывают запуск.

## Жизненный цикл и безопасность

Инициализация вызывается до точки входа игры. `DllMain` должна оставаться минимальной:
не устанавливайте там сложные перехваты, не ждите потоки и не загружайте ресурсы.
`DllMain` выполняется до проверки ABI, поэтому проверка ABI не является песочницей.

При ошибке инициализации DLL должна самостоятельно отменить уже внесённые изменения перед возвратом ошибки.
Хост вызывает завершение успешно инициализированных DLL в обратном порядке. Необязательная `shutdown()` используется
при откате инициализации или явном завершении; при обычном `ExitProcess` её вызов не гарантируется.
Не полагайтесь на неё для сохранения обязательных данных. Выгрузка во время работы не поддерживается,
а завершение не гарантирует удаления DLL из памяти.

Используйте C ABI и `RSCRIPT_CALL`. Не передавайте через границу DLL объекты STL, исключения C++
или память, которую должен освобождать другой модуль. Каждый модуль сам выделяет и освобождает память;
обработчики обязаны перехватывать собственные исключения.
Расширения, устанавливающие перехваты, должны проверять версию игры и учитывать конфликты с другими DLL.

Обычным расширениям доступны `game_module`, путь игры, папка ресурсов и журнал.
`set_engine_api` / `get_engine_api` — частный мост встроенных модулей, а не стабильный публичный интерфейс ресурсов;
сторонние расширения не должны от него зависеть.

## Расширение и проверка

Проект CMake runtime содержит цель `RScriptLogExample`.
Независимому плагину достаточно публичного заголовка и сборки общей библиотеки; весь конвертер подключать не нужно.
Убедитесь, что экспорт называется ровно `RScriptPlugin_GetDescriptor`, без изменения имени компилятором C++.

Добавьте DLL кнопкой **Add DLL...** и явно установите её флажок.
До совместного использования проверьте несовпадение ABI, ошибку инициализации, повторный ID и запуск только с этой DLL.
Расположение журнала указано в руководстве пользователя.

Будущая Wiki DLL сможет при инициализации подключиться к проверенным обработчикам текста и нажатий
и управлять Wiki on/off внутри модуля. Переключение не должно зависеть от выгрузки DLL.
Пока предоставлены только точка подключения и пример журнала, без Wiki, загрузки плагинов или горячего обновления.
