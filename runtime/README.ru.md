# RScript Runtime

[中文](README.zh.md) | [English](README.en.md) | [Русский](README.ru.md)

[Основания реализации](ENGINE_AUDIT.ru.md) · [Разработка DLL](SDK.ru.md)

Экспериментальные DLL для Windows позволяют оригинальной игре загружать распакованные ресурсы и сценарии UTF-8.
Они не воссоздают игру, не изменяют EXE на диске и не требуют замены официальной `RsComp.dll`.
Инструмент рассчитан на CodeX RScript с поддерживаемыми форматами и Windows API, без проверки имени игры,
белого списка хешей EXE и фиксированных адресов. Сейчас сборка и игровые проверки используют 32-битную Windows;
Forest и SevenBridge — примеры для регрессионных проверок, а не список допуска.

## Начало работы

Поместите собранные `RScriptLauncher.exe`, `RScriptHost.dll` и функциональные DLL в одну папку.
Это необязательно должна быть папка игры. Откройте загрузчик:

1. В **Game executable** выберите EXE игры.
2. В **Override resources** выберите папку подменяемых ресурсов; пустое поле означает папку игры.
3. Отметьте нужные DLL и нажмите **Start game**.

Сначала проверяйте копию игры: расширения не перезаписывают ресурсы, но сама игра может записывать сохранения.

| DLL | Назначение |
| --- | --- |
| `RScriptFiles.dll` | Подключение к синхронным файловым импортам по имени API |
| `RScriptResources.dll` | Приоритет распакованных ресурсов и TSC текущего формата |
| `RScriptUnicode.dll` | Символы за пределами CP932 в подменяемых сценариях UTF-8 |

`RScriptHost.dll` загружается автоматически при необходимости, отдельного флажка для неё нет.
При включении Resources или Unicode автоматически включается Files; отключение Files снимает оба флажка.
Если все флажки сняты, игра запускается без внедрения DLL. Изменения действуют со следующего запуска.

**Add DLL...** добавляет другую DLL; по умолчанию она выключена. Загружайте только доверенные файлы:
нативная DLL может читать и изменять весь процесс игры, песочницы нет.
См. [руководство разработчика DLL](SDK.ru.md). Готовой Wiki DLL пока нет; выгрузка DLL во время игры не поддерживается.

## Подмена ресурсов

Сохраняйте структуру папок оригинала, например `scr/2100.tsc`, `grpe/9001.webp`,
`voice/0001.ogg`, `grps/tbox01/.meta.xml`. Полная копия игры в папке подмены не нужна.

Для ресурсов с одинаковым логическим именем действует следующий порядок:

| Тип | Приоритет |
| --- | --- |
| Аудио | `ogg > wav` |
| Сценарии | `tsc > gsc` |
| Изображения | `webp > png > lim > wcg` |
| Составные изображения | Папка компонента с `.meta.xml` `> lwg` |

Храните `.meta.xml` вместе с изображениями, на которые он ссылается: в нём заданы координаты, размеры и имена элементов.
Если подмены нет, используется обычный путь загрузки игры. Если выбранный файл повреждён или неполон,
выдаётся ошибка, а не незаметный переход к файлу с меньшим приоритетом.

Ресурсы преобразуются в памяти по мере обращения, оригинальные файлы не перезаписываются.
Экспортируйте TSC текущей версией LiarsoftTool и сохраняйте в UTF-8, не удаляя сгенерированные метки и метаданные.
Исходники официального компилятора с include, макросами и подобными возможностями здесь не поддерживаются.

TSC сохраняет собственный формат контейнера. Если исходный GSC найден отдельно или в XFL,
раскладка заголовка должна совпадать. Для новой сцены без образца сохраняется заданный формат, без догадок.

## UTF-8

Для перевода UTF-8 включите Resources, Unicode и Files вместе. Оригинальные GSC остаются в CP932.
Если включён только Resources, весь текст TSC должен представляться в CP932.

Сейчас адаптер Unicode поддерживает символы основной многоязычной плоскости, включая распространённые китайские,
японские и русские символы. Дополнительные плоскости, например emoji, и общий механизм сложной текстовой вёрстки не поддерживаются.
Для разных символов вне CP932 доступно не более 1880 позиций словаря глифов; позиции, занятые оригинальной игрой,
уменьшают этот предел. Установите шрифты с нужными символами: успешная загрузка ресурса не гарантирует наличия глифа.

Словарь глифов хранится здесь:

```text
%LOCALAPPDATA%\LiarsoftTool\RScriptRuntime\<key>\glyphs.bin
```

Не удаляйте его, пока используете старые сохранения или историю текста. Копируйте словарь вместе с сохранениями
и сохраняйте прежние пути к игре и папке подмены: другой путь или изменённый EXE использует другой словарь.
Изменения сценария всё равно могут нарушить совместимость старых сохранений.
Несколько экземпляров игры не могут одновременно использовать один словарь.

Не смешивайте общие DLL с ранними DLL только для Forest; используйте полный комплект одной сборки.
Словари глифов раннего прототипа автоматически не переносятся.

Подробности ошибок записываются в `%LOCALAPPDATA%\LiarsoftTool\RScriptRuntime\host-<pid>.log`.
Журналы и словари сохраняются в папке данных пользователя, а не среди ресурсов оригинала.

## Совместимость

Files подключает `CreateFileA`, `ReadFile`, `SetFilePointer`, `GetFileSize` и `CloseHandle`
из обычной таблицы импорта EXE. Unicode использует ANSI GDI для глифов, текста и измерения,
задавая распознавание CP932 только в игровом модуле; региональные настройки системы не меняются.

Отсутствие обязательных API, повреждение импортов или конфликт с чужим перехватом приводят к явной ошибке.
Отложенные импорты, динамически полученные функции, чтение внутри других DLL, перечисление файлов,
отображение в память и асинхронное чтение пока не перехватываются. Видео через MCI также вне пути подмены.
Движки с другими файловыми или текстовыми API могут потребовать расширения общей поддержки;
успешная инициализация DLL сама по себе не доказывает полной совместимости.

## Сборка и проверка

Из корня репозитория можно отдельно собрать runtime без GTK и libcurl.
Нужны 32-битный Windows-компилятор MinGW и соответствующие статические библиотеки WebP и Vorbis/Ogg:

```bash
cmake -S runtime -B build/runtime-win32 \
  -DCMAKE_SYSTEM_NAME=Windows \
  -DCMAKE_C_COMPILER=i686-w64-mingw32-gcc-posix \
  -DCMAKE_CXX_COMPILER=i686-w64-mingw32-g++-posix \
  -DCMAKE_FIND_ROOT_PATH=/path/to/windows-x86-dependencies \
  -DCMAKE_FIND_ROOT_PATH_MODE_INCLUDE=ONLY \
  -DCMAKE_FIND_ROOT_PATH_MODE_LIBRARY=ONLY \
  -DCMAKE_FIND_ROOT_PATH_MODE_PROGRAM=NEVER \
  -DBUILD_TESTING=OFF
cmake --build build/runtime-win32 -j2
```

Архитектура и runtime библиотек должны соответствовать компилятору; не смешивайте библиотеки Windows и Linux.
Результаты находятся в `build/runtime-win32/`. Дополнительный пример журнала — `RScriptLogExample.dll`.

Параметр `-DBUILD_RUNTIME=ON` в основной сборке включает переносимые тесты ресурсов и Unicode.
Для Windows-тестов также нужны Python 3 и библиотека кодирования Vorbis; при кросс-компиляции можно указать `RSCRIPT_WINE`.
Загрузчик и функциональные DLL создаются только при сборке для Windows.

Возможности экспериментальные. Автотесты, проверки в Wine и полное прохождение на настоящей Windows — разные виды проверки.
Совместимость со всеми сценами, сохранениями, шрифтами и сочетаниями плагинов не гарантируется.
Файлы игры необходимо получить законным способом самостоятельно.
