# Правила репозитория

[中文](AGENTS.zh.md) | [English](AGENTS.en.md) | [Русский](AGENTS.ru.md) | [日本語](AGENTS.ja.md)

## Границы изменений

- Проверьте Git, сохраните существующие правки, прочитайте README, настройки CMake и затронутые модули.
- Репозиторий отвечает за архивы, GSC/TSC, кодировки, изображения и аудио. Генерация Ren'Py и среда исполнения относятся к rscript2renpy.
- CLI и GUI Windows/Linux используют общий механизм преобразования без дублирования.
- Неизвестные форматы и поведение устанавливайте по исходным файлам, EXE и воспроизводимому анализу; не угадывайте opcode и пиксельные алгоритмы.
- Оригиналы доступны только для чтения; тесты выполняются на копиях или во временных каталогах. Не удаляйте и не коммитьте закрытые ресурсы, результаты генерации и личные настройки.
- Сохраняйте граничные проверки, ошибки кодировки, предупреждения и безопасную запись файлов. Упрощение не должно ослаблять защиту данных.
- Документы ветки описывают её фактические функции; синхронизация документов не должна сливать функциональный код.

## Документация

- README предназначен пользователю; API и основания из EXE вынесите в справочники, сборку — в руководство сборки.
- Параметры CLI и примеры преобразования ведите только во встроенной справке; README направляет к `liarsofttool -h`.
- Ведите отдельные `.zh.md`, `.en.md`, `.ru.md`, `.ja.md`; файл без суффикса служит выбором языка.
- Согласуйте структуру и факты. Используйте заменяемые пути без личной конфигурации сопровождающего.
- Не включайте дневники задач, решения из переписки, историю коммитов и старые числа тестов. Оставляйте текущее поведение, полезные ограничения и воспроизводимые основания.
- Сохраняйте исходные лицензии, авторство, происхождение и существенные неизвестные. Убирайте ссылки на удалённые документы.

## Проверки

Настройка описана в [руководстве сборки](docs/BUILDING.ru.md). Выполняйте из корня:

```bash
cmake --build build -j2
ctest --test-dir build --output-on-failure
git diff --check
```

- Перед использованием каталога сборки проверьте путь исходников и генератор в CMakeCache; не меняйте его инструментарий на месте.
- Общие преобразования проверяйте через CLI и доступный GUI; межплатформенные изменения требуют сборки Windows и доступных регрессий Wine.
- При изменении формата выхода проверьте чтение, генерацию и lint в rscript2renpy.
- Для документов достаточно ссылок, якорей, блоков кода, фактической справки и diff; пересборка и запуск игры не нужны.
- Отдельно сообщайте тесты, статический анализ и устройства. Не скачивайте пакеты выпуска повторно ради проверки.

## Git и полномочия

- Проверенные независимые задачи коммитьте отдельно и локально, только с относящимися к ним файлами.
- Отправка, теги, релизы и смена версии требуют явного запроса; новые ветки используют `codex/`.
- Без разрешения не запускайте неизвестные EXE, не выполняйте административные действия, глобальную установку и обход прав доступа.
