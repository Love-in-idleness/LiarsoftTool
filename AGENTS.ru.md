# Правила работы над проектом

[中文](AGENTS.zh.md) | [English](AGENTS.en.md) | [Русский](AGENTS.ru.md)

## Начало работы

- Проверьте Git, сохраните существующие изменения. Для поиска используйте `rg`.
- Прочитайте README, CMakeLists.txt и затронутые модули.
  Справочник TSC — `docs/GSC_OPCODE_REFERENCE.md`.
- Локальные пути общие с соседним rscript2renpy: `local.paths.toml`.
  Не зашивайте личные пути сопровождающего в код.

## Границы реализации

- Этот репозиторий отвечает за архивы, GSC/TSC, кодировки, изображения, аудио и EXE.
  Код Ren'Py находится в rscript2renpy.
- CLI и общий GTK4 GUI Windows/Linux вызывают модуль преобразований, не дублируют его.
- Неизвестные форматы и поведение подтверждаются оригинальными файлами и EXE.
  Не угадывайте opcode и алгоритмы пикселей.
- Оригиналы только для чтения. Преобразования и проверка обратимости — на копиях
  или во временных каталогах.
- Сохраняйте локальные `test/`, `CodeXRScript/`, `res_ft/`, `ubai/`.
  Не очищайте и не коммитьте игровые материалы.
- Сохраняйте проверку входов, строгие кодировки, предупреждения и исключение
  неудачных результатов. Упрощение кода не оправдывает удаление защиты.

## Документация

- README предназначен пользователю: назначение, установка, GUI и необходимые замечания.
- Команды CLI, параметры и примеры поддерживаются в справке программы.
  README направляет к `liarsofttool -h`, не дублирует список.
- Все собственные документы проекта имеют полные, синхронные версии `.zh.md`, `.en.md`, `.ru.md`;
  исходный `.md` служит только языковой навигацией. Оригинальные лицензии и сторонние
  юридические тексты сохраняются без перевода.
- Китайская редакция пользователя — основа; английская и русская передают ту же структуру и сведения.
- Внутренние поля парсера, миграция старых данных, реализация ошибок, журналы
  тестов и коммитов не относятся к пользовательскому руководству.
- Оставляйте только влияющие на работу замечания: кодировка, резервная копия,
  версия и неподдерживаемые функции.
- Opcode и анализ EXE — технические материалы: сохраняйте хеши, адреса,
  параметры и неподтверждённые сведения.
- Проверяйте параметры, команды и локальные ссылки. Не меняйте смысл лицензий
  и авторских уведомлений.

## Проверка

- Используйте настроенный каталог сборки. Сначала проверьте исходный путь
  и генератор CMakeCache, не переключайте существующий генератор.
- После кода: `cmake --build build -j2`, `ctest --test-dir build --output-on-failure`,
  `git diff --check`; путь уточняется по локальной конфигурации.
- Общие преобразования проверяются через CLI и доступный GUI.
  Изменения Windows — также целевой сборкой и регрессиями Wine.
- Изменения GSC/TSC и ресурсов требуют проверки чтения, генерации и lint в rscript2renpy.
- Только документация: ссылки и параметры, без повторной сборки всей игры.
- Различайте тесты, статический анализ и игру. Успешная компиляция не доказывает совместимость.

## Git и права

- Проверенную независимую задачу коммитьте локально, только её файлы.
  Запрос пользователя не коммитить имеет приоритет.
- Без явного запроса не отправляйте изменения, не создавайте tag/Release и не повышайте версию.
- Новые ветки имеют префикс `codex/`; предпочтителен текущий checkout.
- Административные действия сначала согласуются. Не устанавливайте сборки глобально
  и не обходите права каталогов.
