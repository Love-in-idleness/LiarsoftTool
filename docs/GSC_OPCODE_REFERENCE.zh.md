# TSC 指令参考

[中文](GSC_OPCODE_REFERENCE.zh.md) | [English](GSC_OPCODE_REFERENCE.en.md) | [Русский](GSC_OPCODE_REFERENCE.ru.md)

本页用于查找 TSC 命令及对应 opcode。翻译对话时修改引号内的文字，
保留自动生成的标签和元数据。导出与回编用法请运行 `liarsofttool -h` 查看。

## 表格说明

- **已命名**：已确认命令名与参数布局。
- **特殊语法**：跳转、VM 运算等生成形式。
- **语义未知**：参数布局已知，但命令名未确认，输出为 `*opcode`，不要自行猜名替换。
- 未识别的指令布局不能导出为可编辑命令。

参数签名中，`E` 为表达式，`D` 为 32 位无符号值，
`H` 为 16 位无符号值，`S` 为 16 位有符号值。
部分参数是带引号的字符串；各代引擎参数可能不同，以生成的 TSC 布局为准。

实现位于 `src/gsc_decompiler.cpp`。命令表用于查阅，不表示每个引擎都使用全部命令。

## 语义未知 opcode 汇总

| Opcode | 已知签名 | 十套样本中出现 | 当前处理 |
|---:|---|---:|---|
| `0x0054` | `E D` | 0 | 保留结构并输出数值 opcode，等待 EXE/官方资料验证命令语义 |

`0x0054` 是“结构已知、名称未知”，不是解析失败。不要在缺乏编译器或运行时证据时猜测命令名。

## VM 编码指令族

opcode 高 4 位非零时，它不是普通命令编号，而是把运算符和寻址方式编码在 opcode 中。低位还包含左右操作数的立即数、临时变量或间接寻址模式。
TSC 以 `*vm 0xHHHH ...` 保存完整可编译形式；下表给出高位族的语义。

| 高位族 | 运算 |
|---:|---|
| `0x1***` | 赋值 `=` |
| `0x2***` | 逻辑或 `\|\|` |
| `0x3***` | 逻辑与 `&&` |
| `0x4***` | 等于 `==` |
| `0x5***` | 大于等于 `>=` |
| `0x6***` | 大于 `>` |
| `0x7***` | 小于等于 `<=` |
| `0x8***` | 小于 `<` |
| `0x9***` | 不等于 `!=` |
| `0xA***` | 加 `+` |
| `0xB***` | 减 `-` |
| `0xC***` | 乘 `*` |
| `0xD***` | 除 `/` |
| `0xE***` | 取模 `%` |
| `0xF***` | 装载/移动 `mov` |

## TSC 元数据行

| 行 | 含义 |
|---|---|
| `;@gsc-byte-format modern-36` / `legacy-28` | 头部长度与 Section D 的声明规则 |
| `;@gsc-schema <name>` | 指令布局（`pre-codex`/`early-short-select`/`early`/`rscript18`/`rscript19`/`modern`） |
| `;@gsc-trailer <hex>` | Section D 之后的全部尾部字节（两张命名入口表 + 名字表），原样写回；缺省为标准空的 9 字节 |
| `;@gsc-trailer-header <u7> <u8>` | 头部第 7、8 个字，即尾部两张命名入口表与名字表的长度来源；缺省为 `4 1` |
| `;@gsc-raw-v1 …` | 无法识别布局时的整文件原始回退 |

TSC 使用 UTF-8 保存，GSC 的输入和输出编码通过 `-e` 指定。
