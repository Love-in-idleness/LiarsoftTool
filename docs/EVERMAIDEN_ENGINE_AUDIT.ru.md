Исторические основания для аудио, шрифтов, пунктуации и загрузки GSC. Выводы ограничены указанной сборкой.
Исследован китайский `Evermaiden/startup_CHS.exe`, не официальный японский EXE.
Поведение патча нельзя распространять на все официальные программы.

- SHA-256: `2dd8004933ae3943485f825c4b88ccea53301e0f68f331a1440a17aeb6106ee5`.
- Адреса — VA PE. Игра не запускалась, каталог не менялся; копии преобразовывались во временном каталоге.

## 1. Пропущенный Vorbis mode 3 WAV

Сканирование всех 13 XFL выявило неподдерживаемый `wav.xfl/2559.wav`. Он хранит OGG после 66-байтного
контейнера, но тег равен `0x6751`, не `0x6771`: Vorbis mode 3 / mode 3 plus,
см. [определения VLC](https://github.com/videolan/vlc/blob/master/include/vlc_codecs.h).
fmt имеет 26 байт, расширение — 8, stereo 44100 Hz, fact — 843757 отсчётов,
data — 250668 байт, OggS начинается на смещении 66.
Сохранены проверки заголовков, страниц и параметров; добавлен только подтверждённый тег.
Запись сохраняет тег и расширение кодека образца, пересчитывая длины, отсчёты и выравнивание по OGG.
Другие непроверенные режимы не разрешались.
CLI: извлечение → запись → извлечение даёт тот же OGG. Полное декодирование FFmpeg даёт PCM SHA-256
`44f63c38a8646a87b4dbc65148c0f3db2bdcc6822d905d7e191a013fcd0ff1ce`.
Тесты проверяют сохранение формата и отказ для `0x6750`.

## 2. Оптимизированные таблицы переноса

Раньше распознавался только CMP SI, imm16. Здесь обе таблицы используют MOV EAX, imm32 / CMP SI, AX / JE:
38 запретов начала строки и 12 запретов конца, всё ещё японская CP932-таблица.

- Таблица 1 начинается с `0x457961`; расширения — `0x213f`, `0x3f21`, CMP SI, BX;
  конец строки — с `0x457b9a`. `0x45786b–0x457875` задаёт BX=`0x2121`.
- Таблица 2 — с `0x45d248`, без трёх расширений; конец строки — с `0x45d45c`.
- Первые два JE конца строки в первой таблице — near, во второй только первый; остальные short.
- Цели: `0x457c54 / 0x457c37` и `0x45d508 / 0x45d4f0`, присваивающие тип запрета.

Проверяется полная последовательность символов, константы с нулевым расширением, сравнения и JE.
Меняются лишь 50 символьных операндов; ASCII-префиксы, расширения, инструкции и переходы сохраняются.
CP932-таблицы проверяются и при уже выбранном GBK charset: частичная локализация не считается полной.

## 3. Перемежающиеся параметры шрифта

В `0x46d738`, `0x46da28`, `0x46e4eb` charset CreateFontA оставался `0x80`, ещё десять — `0x86`.
Между PUSH вставлены загрузка указателя и расчёт веса, поэтому старое непрерывное сравнение их пропускало.
Например `0x46e4df` загружает CreateFontA из `0x4c8024`, `0x46e507` вызывает ESI.
Распознаётся полная наблюдаемая форма вызова, не произвольный PUSH 0x80; меняется только charset.

Оба исправления EXE: `1d6f88e`. GBK → CP1251 → CP932 на копии подтвердил обе таблицы
и 13 шрифтовых операндов, остальные байты не меняются. От оригинала отличаются 201 / 213 / 10 байтов.
Последние десять исходно были GBK-параметрами, поэтому единый CP932 не равен исходному смешанному файлу.

## Другие пути

- WCG: заголовок `0x478150`, версии `0x4781ff`, парные каналы `0x478222 / 0x478233`,
  сначала A `0x478244`, необязательный RGB `0x478250`: совпадает с реализацией.
- Палитра: граница 4096 в `0x47b84d–0x47b85b`, индексы с `0x47a700` соответствуют прошлому исправлению.
  Реальные WCG были только `0x0271`; все остальные структуры этим не проверены.
- LIM: версии `0x4786df` совпадают с CannonBall; реального LIM-образца не было.
- XFL: `0x47629b–0x4762f8` использует lstrcmpiA. ASCII-folding соответствует, но не гарантирует NLS-порядок не-ASCII имён.
- GSC: загрузка около `0x404faf`, сериализация `0x405458` учитывает заголовок 36 байт.
  Все 208 GBK-скриптов структурированно восстановлены без полного gsc-raw.

## Ограничения

IsDBCSLeadByteEx использует CP_ACP, например `0x44dc33–0x44dc35`. Изменение charset и таблиц не меняет
системную кодовую страницу: нужна подходящая локаль Windows или Locale Emulator. Для работы между
страницами требуется анализ чтения символов и API, не замена шрифта и не слепая правка всех PUSH 0.
Изображение, реальные переносы, звук и нативная Windows остаются пользовательской проверкой.

## официальный японский загрузчик и исполнение GSC

Отдельный файл: `Evermaiden/startup_jp.exe`, SHA-256
`88820f28b8f770b486407e55dda28266c6fec42145192d5bc8ad5be21ab895af`.
PE32, ImageBase `0x400000`; ниже VA. Программа не запускалась и не менялась.

| Путь | Бинарное основание | Исправление |
| --- | --- | --- |
| Загрузка GSC | `0x404ee0–0x40526a` читает девять слов заголовка; после кода, строк и данных `0x4051ab–0x4051dd` читает две таблицы по header[7] байтов и имена header[8] байтов | Это исполняемые именованные входы, не просто отладочные данные |
| Именованные входы | `0x404e00–0x404e51` пропускает слот 0, сравнивает имена первой таблицы, возвращает адреса кода второй; jump использует `0x43df90` | Экспорт меток, перенос адресов хвоста после правки, ошибка при отсутствии меток |
| Локальный вызов | opcode 200 `0x43613a–0x4361ab` читает D и десять выражений, сохраняет возврат; `0x43dea0` вызывает `0x405760`, проверяет адрес < размера кода и прибавляет базу | Первый параметр insub — проверяемая и перемещаемая метка |
| Блок данных | `0x4361f3 → 0x43d4e0 → 0x404d50`: нулевой номер возвращается, остальные идут через индекс; MOVSX `0x404d6e` знаково расширяет int16 количества | Отказ для чрезмерного количества/неверного индекса; нулевой номер ничего не копирует |

В японском 0001.gsc TOP1/click/TOP2 находятся в `0xa6 / 0x25c / 0x7da`, REP002 из 2190.gsc — `0xd9c`.
Простой круг без правки не обнаруживает устаревший адрес: нужно менять длину инструкции перед входом.
Имена, слот 0 и заполнение сохраняются, полный код/строки дополнительно не копируются.
Старые TSC с непустыми входами или числовым insub нужно экспортировать заново.

Проверены 208 японских и 205 текущих китайских GSC, в том числе сдвиг адресов на 6 после wait 1 перед реальным входом.
Оба корпуса прошли ASan/UBSan. Регрессии: CannonBall JP 626 / ZH 437, Forest 103, Khime 341, Albatross 91.
