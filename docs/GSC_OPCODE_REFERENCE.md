# GSC opcode 与 TSC 命令对照表

本文档对应 LiarsoftTool 2.0 的实验性 GSC↔TSC 实现。源码事实来源为 `src/gsc_decompiler.cpp`；“样本次数”来自本地十套兼容性资料，不代表所有 RScript 版本都只包含这些 opcode。

## 状态说明

- **已命名**：参数边界和命令名均已确认，TSC 正文通常输出 `*命令名`。
- **特殊语法**：由反编译器转换为跳转、数据、队列分隔或文本语法。
- **语义未知**：参数长度已经确定，可以结构化往返，但尚无可靠命令名；正文输出 `; opcode <十进制值> ...`。
- **完全未知**：参数长度也未知。当前十套样本中没有出现；遇到时整份文件会明确标注无法反编译，并使用旧 `gsc-raw` 兼容回退。

参数签名中的 `E` 为 RScript 表达式值，`D` 为 32 位无符号值，`H` 为 16 位无符号值，`S` 为 16 位有符号值。不同 RScript 代际的少数已命名命令具有不同签名，具体以 TSC 的 `;@gsc-schema` 为准；原代码字节由 `;@gsc-code` 保存，不再生成逐指令的 `;@gsc-instruction`。

`pow`、`gmenuon`、`gmenuset`、`gmenuget` 和 `map` 的命名依据为 UBAI 所附 2012 年版 `RsComp.dll`（SHA-256 `0b1c3cdfc1587f576c30c09b3faa329e88e18fdaddfc0655d1ad398c1654a6a9`）：其编译器分派代码使用 `lstrcmpiA` 匹配命令名后直接写入对应 opcode。

## 语义未知 opcode 汇总

| Opcode | 已知签名 | 十套样本中出现 | 当前处理 |
|---:|---|---:|---|
| `0x0054` | `E D` | 0 | 保留结构并输出数值 opcode，等待 EXE/官方资料验证命令语义 |

`0x0054` 是“结构已知、名称未知”，不是解析失败。不要在缺乏编译器或运行时证据时猜测命令名。

## VM 编码指令族

opcode 高 4 位非零时，它不是普通命令编号，而是把运算符和寻址方式编码在 opcode 中。低位还包含左右操作数的立即数、临时变量或间接寻址模式。

| 高位族 | 运算 | 样本次数 |
|---:|---|---:|
| `0x1***` | 赋值 `=` | 189277 |
| `0x2***` | 逻辑或 `||` | 2511 |
| `0x3***` | 逻辑与 `&&` | 37021 |
| `0x4***` | 等于 `==` | 36014 |
| `0x5***` | 大于等于 `>=` | 35914 |
| `0x6***` | 大于 `>` | 345 |
| `0x7***` | 小于等于 `<=` | 33809 |

## 当前验证范围

- 1894 个 GSC，合计 1,413,100 条指令。
- 观察到 104 种普通 opcode 和 755,935 条 VM 编码指令。
- 全部样本均能生成不含完整 `gsc-raw` 的结构化 TSC，并逐字节重建原 GSC。
- 样本来源：Evermaiden、Khime、Albatross、Forest、Houkago、Sevenbridge、Cannonball、霞外籠逗留記、CNMI、Jeanne。
