## Форматы и исправления

| Элемент | Основание или воспроизведение | Исправление |
| --- | --- | --- |
| LIM только с альфой | `0x43bab6–0x43bac9`: сначала A, RGB только при `0x10` | Не читать отсутствующие три цветовых блока; сохранить альфу, RGB=0 |
| LIM RGB565 | `0x43bd56–0x43bd89`: сдвиг 5/6-битных компонент, не растяжение до 255 | Цвета движка, например белый `(248,252,248)` |
| Прозрачный ключ RGB565 | Тот же путь узнаёт `0x07e0`; отдельная альфа перекрывает после `0x43be10` | Зелёный ключ прозрачен, отдельная альфа имеет приоритет |
| Порядок XFL | `0x41ab05–0x41ab43`: двоичный поиск через lstrcmpiA | Лексикографический ASCII-порядок без учёта регистра, включая сериализацию готовых entries; не естественная сортировка чисел |
| Длинные имена XFL | Поле 32 байта; раньше молчаливое обрезание | Отказ после 31 закодированного байта и при совпадении без регистра; не разрезать CP932 |
| Границы XFL/LWG | Усечённые образцы принимались; короткий LWG мог выйти за границы | Проверки заголовков, таблиц, записей, имён, смещений и длин; отказ для отрицательных XFL-смещений, опасных путей и слишком длинных LWG-имён |
| Windows API кодировок | Для UTF-8 использовались запрещённые flags и указатели символа замены | Специальные параметры UTF-8, строгий отказ для неверного ввода, проверка фактического преобразования |

Правильный порядок ASCII: `1.gsc, 10.gsc, 2.gsc`, не `1.gsc, 2.gsc, 10.gsc`.
Четырёхзначные имена обычно скрывают разницу. Требования API:
[WideCharToMultiByte](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-widechartomultibyte),
[MultiByteToWideChar](https://learn.microsoft.com/en-us/windows/win32/api/stringapiset/nf-stringapiset-multibytetowidechar).
Дефект вызова API сам по себе не доказывает единственную причину существующей ошибки пользователя Windows.
Аудио: [отдельная справка](AUDIO_PROCESSING_AUDIT.ru.md).

## Исторические ограничения и неполное покрытие

| Функция | Граница записи | Основание |
| --- | --- | --- |
| Исходная структура LIM | LIM ↔ lossless WebP; запись — version 3 с отдельными A/R/G/B, без сохранения исходной глубины/сжатия | `0x43ba30` выбирает версию, `0x43ba70 / 0x43bab0` — 16 бит/каналы. Сохраняется RGBA, другие движки проверяются в игре |
| Редактируемый MSK | .msk сохраняется, распаковывается и упаковывается; отдельного MSK → PNG → MSK нет | `0x43ac25` добавляет .msk, `0x43aca9` проверяет BM, `0x43ace7–0x43acf7` принимает BMP 1/8/24 бит. Смена расширения не восстанавливает маску |
| Официальный высокоуровневый TSC | Компилятор структурированного байткода, не полная замена исходного языка RsComp | `0x40e38f–0x40e39d` получает Compile, `0x44f274/0x44f280` — форматы имён TSC. Официальный язык содержит #include и %title, текущий ожидает команды/метки |
| Все зависимости игры | Пофайловое преобразование не проверяет все ссылки на изображения, аудио, скрипты и видео | Нет графа проекта, списка отсутствующих ресурсов и неопределённых динамических ссылок |
| Не-ASCII сортировка Windows | Исправлен ASCII, но не полностью повторено сравнение NLS разных локалей | В EXE lstrcmpiA, здесь ASCII-folding UTF-8-имён, без гарантии японского/китайского/русского порядка |
| Перекодирование PCM/Ogg, ресемплинг | PCM сохраняется; Ogg декодируется в PCM или упаковывается в WAV; без кодирования Vorbis и ресемплинга | Пути PCM/ACM различаются. Актуальные правила — в аудиосправке; упаковка не заменяет перекодирование, несовместимый образец отклоняется |
| Видео | Нет MPG → WebM; видео не включено в установленный список архивируемых ресурсов | `0x431f67` получает mciSendCommandA, `0x431f8f–0x431f9b` открывает mpegvideo. Перенос воспроизведения относится к Ren'Py-проекту |

Первые четыре пункта подходят для развития инструмента ресурсов. Воспроизведение, эффекты, меню и сохранения —
задачи rscript2renpy или движка. EXE 2003 года не подтверждает все поздние opcode.
