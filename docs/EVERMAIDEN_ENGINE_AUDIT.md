## 发现并修复的问题

### 1. 漏识别 Vorbis mode 3 WAV

完整扫描 13 个 XFL 时，旧实现无法处理 `wav.xfl/2559.wav`。
它与已支持的压缩 WAV 一样，在 66 字节封装后直接存放 OGG，
但格式标签是 `0x6751`，不是 `0x6771`。
这两个标签分别对应 Vorbis mode 3 / mode 3 plus，参见
[VLC 的音频格式标签定义](https://github.com/videolan/vlc/blob/master/include/vlc_codecs.h)。

样本具体结构：`fmt` 长度 26、扩展长度 8、双声道 44100 Hz、
`fact` 样本数 843757、`data` 长度 250668；`OggS` 从偏移 66 开始。

修复保留原有头部、OGG 页和参数检查，只额外接受这个已验证的标签。
回写保留模板的格式标签和编解码扩展字节，并按 OGG 重建长度、样本数和补齐字节。
没有顺便放行其他未验证的 Vorbis WAV 模式。

验证：真实样本通过 CLI 提取、回写、再次提取，OGG 逐字节相同；
提取结果通过 FFmpeg 完整解码，PCM 输出 SHA-256 为
`44f63c38a8646a87b4dbc65148c0f3db2bdcc6822d905d7e191a013fcd0ff1ce`。
自动测试覆盖格式保留及拒绝未支持的 `0x6750`。

提交：`2f88429`。

### 2. 漏识别优化后的禁则表

旧实现只识别直接 `CMP SI, imm16` 的机器码。
本 EXE 的两张表使用 `MOV EAX, imm32 / CMP SI, AX / JE`，
前 38 项为行首禁则，后 12 项为行尾禁则；内容仍是 CP932 日文表。

- 第一张表从 `0x457961` 开始；后接 `0x213f`、`0x3f21` 和 `CMP SI, BX`
  三项扩展规则，行尾表从 `0x457b9a` 开始。
  `0x45786b–0x457875` 将 BX 设为 `0x2121`。
- 第二张表从 `0x45d248` 开始，不含这三项扩展；行尾表从 `0x45d45c` 开始。
- 第一张行尾表前两次 JE 为近跳转，第二张只有第一次；其余为短跳转。
- 第一张表分别跳至 `0x457c54` / `0x457c37`，第二张跳至
  `0x45d508` / `0x45d4f0`，将字符标为行首禁则或行尾禁则。

新增识别要求完整匹配已知字符序列、零扩展常量、比较指令和 JE 结构。
只改写 50 个字符操作数，ASCII 前缀、扩展规则、指令和跳转全部保留。
字体 charset 已经是 GBK 时也仍检查 CP932 表，避免把部分汉化误当成全部转换完毕。

### 3. 漏识别夹入指令的字体参数

`0x46d738`、`0x46da28`、`0x46e4eb` 三处 `CreateFontA` charset
仍为 `0x80`，与另外 10 处的 `0x86` 混用。
这些调用在参数压栈之间插入了函数指针载入和字重计算，旧的连续字节匹配跳过它们。
例如 `0x46e4df` 从 `0x4c8024` 载入 `CreateFontA`，`0x46e507` 调用 ESI。

新增规则匹配完整的已观察调用形状，而非任意 `PUSH 0x80`；只替换 charset 操作数。

两项 EXE 修复提交：`1d6f88e`。实际 EXE 副本按 GBK → CP1251 → CP932 转换，
独立逐字节检查确认两张完整表和 13 个已确认字体操作数符合目标值，其他字节不变。
相对原文件分别改变 201 / 213 / 10 字节；最后 10 字节是原来为 GBK 的字体参数，
因此统一到 CP932 后并非与原来的混合 charset 文件完全相同。

## 尚存限制

引擎的 `IsDBCSLeadByteEx` 仍使用 `CP_ACP`，例如 `0x44dc33–0x44dc35`。
字体 charset 和禁则表转换**不会设置系统代码页**，需要匹配的 Windows 区域设置或
Locale Emulator。跨系统代码页自动运行需要进一步核对字符读取和系统 API 路径，
不能只替换字体参数，也不能盲目修改所有 `PUSH 0`。

原游戏中的画面、实际禁则效果、音频播放及真实 Windows 验收仍由使用者完成。
本轮没有游戏内或真实 Windows 验证，没有推送或发布新版本。
