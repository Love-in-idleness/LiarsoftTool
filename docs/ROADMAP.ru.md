## Порядок работ

1. Исправления преобразования ресурсов для японского порта SevenBridge в rscript2renpy.
2. Общий интерфейс Linux/Windows на C API GTK4/libadwaita, вызываемом из C++.
   До замены старого интерфейса проверить минимальное окно и упаковку на обеих платформах.
   Предусмотрены системная, светлая и тёмная темы, английский, русский, упрощённый китайский и японский.
3. Просмотр каталогов, XFL, LWG и вложенных архивов без предварительной распаковки.
   Содержимое читается по запросу; изображения, звук, текст, GSC/TSC и байты показываются в памяти.
4. Расширение VS Code для TSC в отдельной ветке `codex/tsc-vscode`: подсветка,
   диагностика и запуск установленного компилятора. Проверка использует C++ ядро
   и отдельный режим CLI, не создающий GSC.

Общие преобразования, параметры и значения по умолчанию сохраняются.
Предпросмотр не меняет входные файлы; экспорт и преобразование запускает пользователь.
Китайские, английские, русские и японские инструкции обновляются вместе с функциями. Автоматических push, релизов
или повышения версии нет. Это план, а не список уже реализованных возможностей.

## Графический редактор TSC: первая версия в отдельной ветке

По последнему решению `codex/tsc-vscode` предоставляет эпизоды, события и связи, переход к исходнику, статический просмотр и экспорт для оригинального движка.
Приоритет — японская SevenBridge, профиль Forest сохранён; другие игры пока не добавляются.
Это первая версия, требующая приёмки в оригинальной игре, не симулятор движка и не часть master. См. [руководство](../tsc-vscode/README.ru.md).

Экспериментальный `--pure-renpy` относится к долгосрочному
[плану rscript2renpy](https://github.com/Love-in-idleness/rscript2renpy/blob/main/docs/ROADMAP.md).
В текущем этапе нет ни соответствующего флага, ни генератора нативных сценариев Ren'Py.
