# Техническая справка: аудиоконтейнеры

[中文](AUDIO_PROCESSING_AUDIT.zh.md) | [English](AUDIO_PROCESSING_AUDIT.en.md) | [Русский](AUDIO_PROCESSING_AUDIT.ru.md) | [日本語](AUDIO_PROCESSING_AUDIT.ja.md)

[Документация](README.ru.md)

Правила WAV/OGG и основания из CannonBall. Обычные команды: `liarsofttool -h`.

## Преобразование

| Вход | Результат |
| --- | --- |
| WAV с полным потоком Vorbis | Извлечение OGG |
| Обычный PCM WAV | Без изменений |
| OGG | По умолчанию декодирование в 16-битный PCM WAV |
| OGG с `--vorbis-in-wav` | Сжатый поток в контейнере WAV |

PCM сохраняет частоту и один/два канала, без ресемплинга. Vorbis-in-WAV строит контейнер
по параметрам источника, без WAV-образца. PCM не восстанавливает исходные сжатые байты;
побайтовое совпадение нового WAV с оригинальным контейнером не требуется.

Ищите блоки RIFF, а не Ogg на фиксированном смещении 66. Поддерживаются полные потоки
Vorbis 1/1+/3/3+; разделённые заголовки mode 2 не считаются полным Ogg. Проверяются границы
страниц, последовательность, CRC и EOS. Метаданные редактора не попадают в аудио.

## Основания из оригинала

`Cannonball.exe`, SHA-256:
`df4b5b6dffc7002370d0772869baaba551b08fca970e92609ca64b08174f89ba`.
Ниже виртуальные адреса PE.

| Адрес | Поведение |
| --- | --- |
| `0x41257a` | Загрузка vorbis.acm и регистрация драйвера ACM |
| `0x4411fe–0x441221` | Определение PCM и поиск data |
| `0x4414b0–0x44153e` | Чтение сжатого формата и создание параметров PCM |
| `0x441573` | Открытие потока преобразования ACM |
| `0x441678–0x441682` | Поиск сжатого data |
| `0x441862` | Преобразование аудио |

Расширение WAV не определяет содержимое: проверяйте контейнер.
Медиакоманды RsComp.dll описаны в [анализе DLL](RSCOMP_MEDIA_AUDIT.ru.md).

## Сопровождение и проверка

Реализация: `src/wav_ogg.cpp`; тесты: `tests/wav_ogg_test.cpp`.
Проверяются извлечение/упаковка, декодирование PCM, повреждённые данные и рекурсия.
Приём контейнеров оригинальной игрой ещё требует проверки в игре.
