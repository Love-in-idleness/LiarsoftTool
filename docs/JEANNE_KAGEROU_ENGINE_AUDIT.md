## 字体转换漏改：已修复

每个 EXE 都有 12 处直接通过 IAT 调用 `CreateFontA` 的路径。
旧识别器只转换其中 6 处；其余 6 处的 charset 在转换为 GBK 后仍为 `0x80`。
区别不是新字符编码，而是编译器把字重/高度计算穿插在参数 PUSH 中，
或使用已清零的 EBP/EBX 来压入零参数。

| 路径 | j.exe 的 charset 操作数字节 | kagerou.exe 的 charset 操作数字节 |
| --- | --- | --- |
| EBP 零参数、固定字重 | `0x45c173` | `0x457e83` |
| 穿插 EDI 字重计算、EBP 高度 | `0x45ec5e` | `0x45c61e` |
| 穿插 EDI 字重计算、EBX 高度 | `0x45efeb`, `0x45f33e` | `0x45c9ab`, `0x45ccfe` |
| EBX 零参数、EAX 字重计算 | `0x45fa6f` | `0x45d42f` |
| 立即数零参数、EAX 字重计算 | `0x45fcd6` | `0x45d696` |

现在完整匹配已观察到的调用形状，只把 IAT 地址作为变量，修改 charset 的一个字节。
不扫描并替换任意 `PUSH 0x80`，不改动分支、函数地址、字重或字号。
新形状同时用于文件识别与转换，只有这些形状的文件也可以转换。

- CP932 → GBK 后两份 EXE 的全部 12 个 charset 操作数均为 `0x86`。
- CP932 → GBK → CP1251 → CP932 后两份 EXE 均与原文件逐字节一致。
- 原有禁则表已经被正确识别：各有一份 50 比较项和一份 53 比较项。
  j.exe 位于 `0x44d104` / `0x45aca6`，kagerou.exe 位于 `0x4499d4` / `0x455126`。
  扩展的三个 ASCII 组合不变，未增加新的禁则语义。
- 运行时系统代码页仍须与文本一致；字体 charset 补丁不等于切换所有 ANSI API 的代码页。

## LWG 名称 / XML：已修复

《霞外籠逗留記》的 `grps.xfl` 中含 46 个零数据条目，
其中 23 个名字是 Photoshop 风格的 `</Layer set>`。
这些条目按现有 `empty="1"` 规则保留，但名字过去直接写入 XML，
导致 `cgview`、`excompane`、`extrmenu`、`fontcompane`、`scview` 的
`.meta.xml` 不符合 XML 语法。普通 XML 解析器、包括移植项目的 ElementTree 会报错。

公共提取器现在转义名字中的 `& < > " '`，回编器一次性还原五种 XML 实体，
避免把原名里的字面量 `&lt;` 二次解码。
回编查找实际文件时使用与提取器相同的文件系统字符替换规则，
修复含保留字符的非空图层无法重新绑定其图片的问题；写回 LWG 的名字仍是原名。

两游戏合计 32 个 LWG 提取→回编均与原文件逐字节一致，
包括全部空条目的名字、坐标、Flag 和顺序。生成的 32 份 XML 均通过 ElementTree 解析。
已生成的旧非法 XML 需要从原封包重新提取；本次未覆盖正式 Ren'Py 工程。
